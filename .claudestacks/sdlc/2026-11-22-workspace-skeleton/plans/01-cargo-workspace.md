# Cargo Workspace Implementation Plan

**Goal:** Create the nine-crate Cargo workspace, with its pinned toolchain, whose normal dependency edges are exactly those of spec §4.

**Architecture:** A virtual root manifest (no `[package]`) centralises `[workspace.package]`, `[workspace.dependencies]` and `[workspace.lints]`. Every member under `crates/` inherits them. Eight library crates have export-only roots carrying only a `//!` block. One binary crate, `herdrify-cli`, builds the `herdrify` executable, which prints its version line. Normal edges point only downward: L0 (core, hc, app) has none, L1 depends on L0, and L2 (cli) depends on L1 and core (spec §2, §4).

**Tech Stack:** Rust 1.94.1 (pinned by `rust-toolchain.toml`), cargo 1.94.1, edition 2024, resolver 3. No external crates.

**Content authority:** spec §2, §3, §4 (4.1–4.3), and §9 rows 1–4, 7 and 9; acceptance §10 items 3, 4 and 5 (for the files this plan creates).

## Order of work

### Task 1 — Create the workspace, its nine members and the version line

**Files:**
- Create `Cargo.toml`, `rust-toolchain.toml`: the workspace root, copied from `<probe>`.
- Create, for each of the eight libraries (`herdrify-core`, `herdrify-hc`, `herdrify-app`, `herdrify-lua`, `herdrify-herdr`, `herdrify-store`, `herdrify-git`, `herdrify-testkit`): `crates/<name>/Cargo.toml`, `crates/<name>/README.md` and `crates/<name>/src/lib.rs`, each copied from `<probe>`.
- Create `crates/herdrify-cli/Cargo.toml` and `crates/herdrify-cli/README.md`, copied from `<probe>`.
- Create and test `crates/herdrify-cli/src/main.rs`: test first, then the implementation. The end state equals `<probe>/crates/herdrify-cli/src/main.rs`.
- Create `Cargo.lock`: cargo writes it during the first build. It must equal `<probe>/Cargo.lock`.

**Change:**
- The root manifest declares no `[package]`. Its `[workspace.dependencies]` lists the eight library crates by `path` and `version = "0.0.0"`.
- Every member inherits `edition`, `rust-version`, `license`, `repository` and `authors` from the root, sets `version = "0.0.0"` and `readme = "README.md"`, opts into `[lints] workspace = true`, and declares its herdrify dependencies as `{ workspace = true }`.
- Each library root holds only its `//!` block:
  - first, a line saying what the crate is
  - next, the line "This crate root holds no logic, so it carries no unit tests."
  - then why the crate exists, its Responsibilities and its Non-responsibilities
- In `main.rs`:
  - a private function `version_line` returns `"herdrify "` followed by the package version from `CARGO_PKG_VERSION`
  - `main` prints that line to standard output
- No external crate and no Cargo `[features]` are added.

**Proof:** written first, seen failing, then passing.
- `version_line_names_the_command_and_its_package_version`, in `crates/herdrify-cli/src/main.rs`'s `#[cfg(test)] mod tests`: asserts that `version_line()` equals `"herdrify "` followed by the package version. Write it while `main.rs` holds only the `//!` block, the test module and an empty `main`. It fails to compile because `version_line` does not exist. Then add `version_line` and the `println!` in `main`, and it passes.

**Done when:**
- These commands pass:
  - `cargo test -p herdrify-cli --all-targets` passes, running the one test above.
  - `cargo run -q -p herdrify-cli` prints exactly `herdrify 0.0.0` and exits 0 (spec §4.2, `evidence/probe-run.txt`).
  - For each of the nine crates, `cargo tree -e normal -p <crate> --depth 1 --prefix none --format '{p}' | sed 's/ (.*//'` prints the crate itself plus exactly its §4 dependencies (`evidence/probe-edges.txt`).

  - `cargo metadata --format-version 1 --no-deps` lists exactly the nine `herdrify-*` packages. The nested probe workspaces under `.claudestacks/` are not members (spec §9, `evidence/probe-nested-workspaces.txt`).

## Risks

- **Riskiest step: an edit drifting from `<probe>`.** The gate was proven only on the exact probe files (spec §5). Any byte of difference is unproven. That includes rewording a `//!` block, reordering manifest keys, or changing `main.rs` formatting after `cargo fmt`. The `diff` checks in Task 1 catch drift.
- **The task is large but mechanical.** The intermediate states are unproven: a root manifest without all its members, or eight libraries without the binary. So the whole workspace lands in one task and one commit, and every commit passes the Definition of Done on its own.
- **An empty `main` fails clippy** (`missing_const_for_fn`, `evidence/probe-main-plain.txt`). The failing-first state of the test uses an empty `main` only while the test does not compile. Committing that state is never an option.
- **A stray directory under `crates/` breaks every cargo command** (spec §9, `evidence/probe-stray-dir.txt`). No directory under `crates/` is created other than the nine members.
- **Publishing is out of scope.** `cargo package` fails for a member with an inter-crate dependency until its dependencies are published (spec §4, §9, `evidence/probe-package.txt`). No task runs `cargo package` or `cargo publish` (spec §11).
- **Options not taken:** `const fn main() {}` (spec §4.2 case A), and the `herdrify-core` → `herdrify-testkit` dev-dependency, which arrives with the first core test (spec §11).
